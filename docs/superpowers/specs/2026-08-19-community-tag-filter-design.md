# 学习社区标签筛选修复设计

## 1. 目标

修复学习社区热门标签筛选缺少状态提示和清除入口的问题。用户点击热门标签后，筛选条件需要在讨论选项卡区域中明确展示；用户点击关闭按钮后，只清除标签筛选，并恢复当前选项卡下未经标签过滤的完整讨论列表。

本次修改不改变社区页面信息架构、讨论排序规则、收藏逻辑、文本搜索、发帖与回复流程，也不覆盖工作区中尚未提交的圆角、头像等视觉调整。

## 2. 根因

当前热门标签按钮直接执行 `setKeyword(tag)`，把标签筛选写入文本搜索框使用的 `keyword` 状态。由此产生三个问题：

- 标签筛选与自由文本搜索没有独立语义；
- 切换“最新讨论 / 热门讨论 / 我的收藏”只改变选项卡状态，不会清空 `keyword`，列表继续被过滤；
- 页面没有明确标识当前正在按标签筛选，也没有独立清除入口。

根因是两类筛选条件共享同一个状态，而不是选项卡切换本身失效。

## 3. 已确认方案

新增独立的 `selectedTag: string | null` 页面状态，将选项卡、标签和文本搜索作为三个可组合但互不覆盖的筛选条件。

### 3.1 热门标签

- 点击热门标签时设置 `selectedTag`，不修改搜索框的 `keyword`；
- 同一时间只允许选择一个热门标签；
- 再点击其他热门标签时直接替换当前标签；
- 标签匹配使用帖子 `tags` 数组的精确匹配，不使用标题、正文或课程名称的模糊匹配；
- 热门标签按钮通过 `aria-pressed` 暴露选中状态，并提供与现有视觉体系一致的选中样式。

### 3.2 已选标签组件

- 组件位于“我的收藏”选项卡右侧、搜索框左侧；
- 显示为单行胶囊标签，内容为 `#标签名` 和关闭图标；
- 仅在 `selectedTag` 非空时渲染，未选择标签时不占据布局空间；
- 关闭按钮使用明确的无障碍名称，例如“清除标签：React”；
- 点击关闭按钮只执行 `setSelectedTag(null)`，保留当前选项卡和文本搜索内容。

### 3.3 选项卡行为

- 切换“最新讨论 / 热门讨论 / 我的收藏”时保留 `selectedTag`；
- 当前标签始终在选项卡右侧可见，避免用户误以为列表数据缺失；
- 点击关闭按钮后，列表恢复为当前选项卡与当前文本搜索共同决定的结果；
- “我的收藏”仍先限制为已收藏帖子，再应用标签和文本搜索。

### 3.4 文本搜索

- 搜索框继续使用 `keyword`；
- 搜索范围保持为标题、正文、课程名称和帖子标签；
- 文本搜索与热门标签可同时生效；
- 清除已选标签不清空搜索框，避免丢失用户主动输入的条件。

### 3.5 发布讨论

成功发布讨论后沿用现有行为，切换到“最新讨论”并清空文本搜索；同时清空 `selectedTag`，确保新发布的话题可以立即出现在完整列表中。

## 4. 筛选数据流

```text
原始 posts
→ 若选项卡为 BOOKMARKED，仅保留 bookmarked=true
→ 按 LATEST 或 HOT 规则排序
→ 若 selectedTag 非空，仅保留 post.tags 精确包含 selectedTag 的帖子
→ 若 keyword 非空，对标题、正文、课程名称和标签执行模糊搜索
→ 渲染 visiblePosts 或空状态
```

`visiblePosts` 继续通过 `useMemo` 派生，依赖项增加 `selectedTag`。不创建第二份帖子列表状态，避免源数据与筛选结果不同步。

## 5. 响应式布局

- 桌面端保持选项卡组在左、搜索框在右；已选标签紧跟“我的收藏”；
- 选项卡与已选标签放入可横向滚动的同一行，窄屏时不压缩按钮文字；
- 搜索框继续在小屏下换到下一行并占满可用宽度；
- 胶囊标签沿用页面的靛蓝主色、浅色背景和圆角语言，不引入新的设计依赖或动画库。

## 6. 变更边界

主要修改 `educloud-frontend/student-portal/src/pages/Community.tsx`：

- 新增 `selectedTag` 状态；
- 调整 `visiblePosts` 派生逻辑；
- 新增已选标签胶囊及清除按钮；
- 将热门标签点击行为从修改 `keyword` 改为修改 `selectedTag`；
- 增加选中态和无障碍属性。

不修改 Zustand 社区数据仓库、帖子类型、路由、接口、持久化机制或后端服务。

## 7. 验证策略

学生端当前没有自动化测试运行器，本次不为单个交互引入新的测试框架。通过可重复的真实浏览器行为断言完成红绿回归。

### 7.1 修复前红灯

- 打开学习社区，记录完整帖子数量；
- 点击一个有匹配数据的热门标签；
- 验证搜索框被标签文本占用，选项卡区域没有独立已选标签和清除按钮；
- 切换三个选项卡，验证筛选状态持续存在且没有可发现的恢复入口。

### 7.2 修复后绿灯

- 点击热门标签后，搜索框内容保持不变；
- “我的收藏”右侧显示唯一的已选标签胶囊；
- 列表只包含 `post.tags` 精确包含该标签的帖子；
- 切换三个选项卡后胶囊仍可见，列表符合“选项卡 + 标签”的组合结果；
- 点击胶囊关闭按钮后标签消失，当前选项卡的完整列表恢复；
- 输入文本搜索后再清除标签，搜索内容和搜索结果仍保留；
- 选择无匹配结果的标签时显示现有空状态；
- 成功发布讨论后标签筛选被清除。

### 7.3 工程回归

- 运行学生端 TypeScript 类型检查；
- 运行学生端生产构建；
- 检查浏览器控制台没有新增错误；
- 检查桌面端和窄屏布局，不出现选项卡文字挤压或横向页面溢出；
- 运行差异空白检查，并确认只修改已批准的社区筛选范围。

## 8. 成功标准

热门标签筛选成为独立、可见、可清除的页面状态。用户始终能够识别列表为何被过滤，并能通过“我的收藏”右侧的关闭按钮恢复当前选项卡下的完整讨论列表；文本搜索、排序、收藏、发帖和回复行为保持不变。
