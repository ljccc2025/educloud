# 教师端“发布作业”液态玻璃弹窗设计

## 1. 目标

在教师端 `/assignments`“作业批改”页面增加“发布作业”入口，使教师能够在不离开当前批改上下文的情况下创建作业草稿或立即发布作业。

本次采用与“新建课程”、创建考试和创建直播一致的液态玻璃弹窗语言，并完成教师端 Mock 数据闭环。设计预留与现有后端规范中 `DRAFT → PUBLISHED → CLOSED` 状态机、迟交规则和提交次数规则对接的字段，不引入新的前端技术或状态管理依赖。

## 2. 已确认范围

### 2.1 本期包含

- 在“作业批改”页面标题区增加“发布作业”主按钮。
- 在当前页面上方打开液态玻璃弹窗，不新增独立发布路由。
- 支持保存草稿和立即发布。
- 支持编辑草稿和将草稿发布。
- 发布后立即更新教师端作业列表并选中新作业。
- 新发布作业尚无提交时显示明确空状态。
- Mock API 支持本次浏览器会话内的创建、更新和发布状态变化。

### 2.2 本期不包含

- 不同步修改学生端作业中心数据。
- 不实现真实后端、数据库或跨端消息通知。
- 不增加作业附件、评分量表、定时发布、班级分组或指定学生发布。
- 不实现关闭作业操作；`CLOSED` 仅作为兼容后端规范的类型状态保留。
- 不承诺浏览器刷新后的 Mock 数据持久化。

## 3. 现有项目约束

- 教师端使用 React、TypeScript、Vite、Zustand、Tailwind CSS 风格类和 Lucide 图标。
- 当前 `AssignmentGrade` 直接从 `api.getAssignments()` 读取 Mock 作业并在组件内维护选择状态。
- 当前教师端 `Assignment` 只包含批改展示所需字段，没有作业状态、迟交规则和最大提交次数。
- 当前 Mock API 只提供读取作业与评分方法，没有创建、更新或发布作业方法。
- 后端规范已经定义：
  - 作业状态为 `DRAFT → PUBLISHED → CLOSED`；
  - 发布时总分必须大于 `0`；
  - 截止时间必须晚于发布时间；
  - `maxAttempts` 至少为 `1`；
  - 迟交行为由 `allowLateSubmission` 控制。

本设计沿用这些既定规则，避免教师端原型与后续真实接口再次分叉。

## 4. 交互设计

### 4.1 页面入口

“作业批改”页面顶部改为左右布局：

- 左侧保留页面标签、标题和说明；
- 右侧增加带 `Plus` 图标的“发布作业”主按钮；
- 窄屏时按钮在标题下方占满可用宽度。

点击按钮后：

1. 当前作业列表和批改内容保留在背景中；
2. 页面覆盖靛蓝半透明遮罩和背景模糊；
3. 居中显示液态玻璃发布弹窗；
4. 焦点自动进入“作业标题”输入框。

### 4.2 液态玻璃弹窗

弹窗沿用已确认的课程创建风格：

- 遮罩：`bg-indigo-950/25` 与 `backdrop-blur-xl`；
- 装饰：左侧琥珀色、右侧靛蓝色低透明模糊光晕；
- 面板：白色半透明背景、白色细边框、`backdrop-blur-2xl`、圆角和柔和阴影；
- 最大宽度采用中等表单尺寸，最大高度受视口限制，内容超出时只在弹窗内部滚动；
- 右上角提供关闭按钮。

### 4.3 默认字段

| 字段 | 类型 | 默认值 | 规则 |
|---|---|---|---|
| 所属课程 | 下拉选择 | 空 | 保存草稿和发布均必填，只展示当前教师拥有的课程 |
| 作业标题 | 单行文本 | 空 | 保存草稿和发布均必填，提交前去除首尾空格 |
| 作业说明 | 多行文本 | 空 | 发布必填，草稿可为空 |
| 截止时间 | `datetime-local` | 空 | 发布必填且必须晚于当前时间，草稿可为空 |
| 满分 | 数字 | `100` | 发布时必须大于 `0` |

### 4.4 高级提交规则

默认折叠显示一行摘要：

```text
提交规则 · 最多 1 次 · 不允许迟交
```

展开后提供：

- 最大提交次数：整数输入，默认 `1`，发布时必须至少为 `1`；
- 允许迟交：开关，默认关闭。

首期不加入更多高级字段，保证弹窗仍适合日常快速发布。

### 4.5 底部操作

弹窗底部提供三个动作：

- `取消`：不保存并关闭弹窗；
- `保存草稿`：执行草稿级校验并保存；
- `立即发布`：执行完整发布校验并发布。

保存或发布过程中，所有关闭和提交入口均禁用，按钮显示进行中状态，防止重复创建。

## 5. 作业状态与列表行为

### 5.1 草稿

保存草稿成功后：

- 新作业插入左侧作业列表顶部；
- 新作业自动成为当前选中项；
- 作业卡显示“草稿”状态标签；
- 右侧详情显示已填写内容和“编辑草稿”“立即发布”操作；
- 批改统计和提交列表不显示为可批改状态。

编辑草稿复用同一弹窗，打开时回填已有数据。保存后只更新原对象，不创建第二条作业。

### 5.2 发布

立即发布成功后：

- 新作业或原草稿状态变为 `PUBLISHED`；
- 记录发布时间；
- 作业自动选中并位于列表顶部；
- `submissionCount` 和 `gradedCount` 均为 `0`；
- 右侧显示作业详情和“等待学生提交作业”的空状态。

只有已发布课程中的作业可以立即发布。如果选择草稿或已归档课程，表单保留当前内容并提示“当前课程尚未发布，作业可以保存为草稿，但不能立即发布”。

### 5.3 已发布与已关闭

- 已发布作业继续使用现有提交与批改功能；
- 已关闭作业可正常读取历史提交和批改结果；
- 本期不提供已发布作业编辑或关闭入口。

## 6. 类型与 Mock 数据模型

教师端新增：

```ts
type AssignmentStatus = 'DRAFT' | 'PUBLISHED' | 'CLOSED';
```

`Assignment` 增加：

- `status: AssignmentStatus`；
- `allowLateSubmission: boolean`；
- `maxAttempts: number`；
- `publishedAt?: string`。

现有 Mock 作业统一补为 `PUBLISHED`，默认不允许迟交、最大提交次数为 `1`。现有批改字段和 `Submission` 结构保持不变。

创建和更新请求使用独立输入类型，允许草稿阶段的说明与截止时间为空，避免把展示实体直接当作表单请求。

## 7. 组件边界

### 7.1 `AssignmentPublishModal`

职责：

- 使用 Portal 渲染遮罩和玻璃面板；
- 管理焦点、Escape、焦点循环、背景滚动锁定和关闭后的焦点回归；
- 区分创建与编辑标题；
- 管理保存/发布中的禁用状态和全局错误提示；
- 组合 `AssignmentForm`，不包含作业列表逻辑。

### 7.2 `AssignmentForm`

职责：

- 管理字段值和高级规则展开状态；
- 根据“保存草稿”或“立即发布”执行不同校验；
- 在字段附近显示校验错误；
- 通过明确回调提交草稿或发布请求；
- 不直接访问 Mock API。

### 7.3 `AssignmentGrade`

职责：

- 加载课程与作业；
- 控制发布弹窗的打开、关闭和编辑对象；
- 调用 Mock API 创建、更新或发布；
- 将返回作业合并到列表顶部并设为选中项；
- 根据作业状态渲染草稿详情、等待提交空状态或现有批改表。

### 7.4 Mock API

新增方法：

- `createAssignmentDraft(data)`；
- `updateAssignmentDraft(id, data)`；
- `publishAssignment(id)`；
- 直接发布采用“创建草稿后发布”这一相同状态路径，不维护第二套创建逻辑。

API 返回复制后的数据结构，组件不得直接修改共享 Mock 数组。

## 8. 数据流

### 8.1 保存草稿

```text
点击发布作业
→ 填写课程和标题
→ 保存草稿
→ AssignmentForm 草稿校验
→ createAssignmentDraft / updateAssignmentDraft
→ 返回 DRAFT Assignment
→ 列表顶部合并并选中
→ 关闭弹窗并恢复按钮焦点
```

### 8.2 立即发布

```text
点击立即发布
→ AssignmentForm 完整校验
→ 校验所选课程状态
→ 新作业先创建草稿，已有草稿先更新
→ publishAssignment
→ 返回 PUBLISHED Assignment
→ 列表顶部合并并选中
→ 显示等待学生提交空状态
```

相同 ID 的作业使用替换合并，不能因草稿转发布产生重复列表项。

## 9. 校验与错误处理

### 9.1 草稿校验

- 所属课程不能为空；
- 作业标题去除首尾空格后不能为空；
- 已填写的满分必须为有效正数；
- 已填写的最大提交次数必须为正整数。

### 9.2 发布校验

在草稿校验基础上增加：

- 作业说明不能为空；
- 截止时间不能为空且必须晚于当前时间；
- 满分必须大于 `0`；
- 最大提交次数至少为 `1`；
- 所属课程必须处于 `PUBLISHED`。

### 9.3 异常处理

- 字段错误显示在字段下方，不关闭弹窗；
- API 错误显示在弹窗底部的告警区域，保留所有输入；
- 失败时不修改作业列表、选中项或状态；
- 保存/发布成功后才关闭弹窗；
- 弹窗卸载后不继续更新本地提交状态。

## 10. 可访问性与响应式

- 弹窗使用 `role="dialog"`、`aria-modal="true"` 和可关联标题；
- 打开时聚焦作业标题，Tab/Shift+Tab 保持在弹窗内；
- Escape 在非提交状态下关闭弹窗；
- 关闭后焦点回到触发按钮或草稿操作按钮；
- 打开期间锁定 `document.body` 滚动，并在任何关闭路径恢复；
- 窄屏下页面标题与按钮改为纵向布局，弹窗保留安全边距并使用内部滚动；
- 开关、折叠入口和状态标签均提供可读文本，不能只依赖颜色表达状态。

## 11. 验收与验证

### 11.1 功能验收

- 可从“作业批改”页打开发布弹窗；
- 可保存只有课程和标题的草稿；
- 可重新打开并编辑草稿；
- 可将完整草稿发布且列表中不重复；
- 可直接创建并发布作业；
- 新发布作业显示 `0` 提交和等待提交空状态；
- 过去截止时间、零分、无效提交次数和未发布课程均不能发布；
- API 失败时保留输入且列表不变化。

### 11.2 交互验收

- Escape、关闭、取消均正确恢复滚动和焦点；
- 提交期间不能重复点击或关闭；
- 桌面与窄屏下弹窗可完整操作；
- 现有作业选择记忆和批改流程不回退。

### 11.3 工程验证

- 运行教师端 TypeScript 类型检查；
- 运行教师端生产构建；
- 运行差异空白检查；
- 使用真实浏览器验证草稿、发布、编辑、校验、焦点和响应式流程；
- 当前教师端未配置自动化测试运行器，本期不为单个 UI 功能引入新的测试框架。

## 12. 成功标准

教师能够在“作业批改”页面内完成作业草稿创建、草稿编辑和立即发布；交互与现有液态玻璃创建弹窗一致；发布规则与项目后端规范兼容；新作业能够立即进入教师端列表并呈现正确空状态；现有批改流程、选择记忆和其他工作区修改不受影响。
