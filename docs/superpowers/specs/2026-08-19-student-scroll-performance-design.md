# 学生端滚动性能优化设计

## 1. 目标

修复学生端首页滚动时的掉帧问题，同时保留现有 Galaxy 动态星空的视觉方向。优化聚焦已经通过真实浏览器隔离出的 WebGL 渲染瓶颈，不改变学生端页面信息结构、路由、业务数据或既有交互。

## 2. 诊断结论与基线

在 Chromium、`1440 × 900` CSS 视口、DPR 2、4 倍 CPU 降速条件下，以相同的 3 秒全页滚动脚本测得：

| 场景 | 平均帧率 | P95 帧间隔 | Canvas |
|---|---:|---:|---|
| 首页 Galaxy 开启 | 84.3–84.8 FPS | 16.7 ms | `2864 × 1378` |
| 课程页（无 Galaxy） | 119.3–120 FPS | 8.4 ms | 无 |
| 首页诊断性停止 WebGL | 120 FPS | 8.5 ms | 上下文已停止 |

采样期间没有 Long Task。课程页与首页共用导航栏，课程页仍能维持约 120 FPS，因此 React 列表、数据请求、导航栏滚动状态和毛玻璃不是主要瓶颈。Galaxy 是本次可复现的主因。

## 3. 根因

### 3.1 Canvas 尺寸计算错误

现有实现先读取容器 CSS 尺寸，再手工乘以 DPR 传给 `renderer.setSize`。OGL 同时把该值写入 Canvas 的显示尺寸和缓冲区尺寸，导致 DPR 2 环境中的 Canvas 显示尺寸也被放大，首页实际创建约 395 万像素的渲染目标。

### 3.2 着色器像素成本高

片元着色器包含 4 个星层，每层又检查相邻 9 个网格，并执行多次哈希、三角函数、颜色转换、透明混合和辉光计算。该成本与像素数和绘制频率相乘，高分屏上对 GPU 填充率影响明显。

### 3.3 无条件持续绘制

现有 `requestAnimationFrame` 循环始终按屏幕刷新率调用 `renderer.render`：

- 首页 Hero 滚出视口后仍绘制；
- 浏览器标签页隐藏时没有显式释放调度；
- 用户开启“减少动态效果”时仍绘制；
- `disableAnimation` 仅停止时间更新，仍每帧提交 WebGL 绘制。

### 3.4 次要开销

- 默认 `focal` 和 `rotation` 数组在组件重新渲染时可能形成新的依赖引用，触发 WebGL effect 重建；
- 首页外层设置了 `pointer-events-none`，实际无法产生鼠标交互，但组件仍在每帧更新鼠标平滑状态；
- `three` 当前未被学生端源码引用，不进入本次运行时瓶颈范围，不因本次修复擅自调整依赖。

## 4. 已确认方案

采用“保留动效的自适应渲染”方案。

### 4.1 正确管理 DPR

- 通过 OGL `Renderer` 的 `dpr` 参数管理缓冲区像素比；
- `renderer.setSize` 只接收容器的 CSS 宽高，不再手工乘 DPR；
- DPR 默认上限设为 `1.5`，避免高分屏像素数平方增长；
- Canvas CSS 尺寸始终与容器一致。

### 4.2 限制星空绘制频率

- Galaxy 作为慢速装饰背景，默认最大绘制频率设为 `30 FPS`；
- 浏览器仍可按 60/120 Hz 独立处理滚动和合成；
- RAF 回调可以继续作为轻量调度器，但只有达到帧间隔时才更新 uniform 并提交 WebGL 绘制；
- 时间 uniform 使用真实时间，不因跳帧改变动画速度。

### 4.3 可见性与动效偏好

- 使用 `IntersectionObserver` 判断 Galaxy 容器是否与视口相交；
- 使用 `document.visibilityState` 判断标签页是否可见；
- 使用 `matchMedia('(prefers-reduced-motion: reduce)')` 响应系统动效偏好；
- 只有“容器可见、标签页可见、未要求减少动态效果”三项同时满足时才持续调度；
- 离屏或标签页隐藏时取消 RAF；重新可见时从当前时间恢复，不补算积压帧；
- 减少动态效果模式只渲染静态首帧。

### 4.4 生命周期稳定性

- 默认焦点和旋转值提升为模块级只读常量，避免默认数组引用变化；
- 使用 `ResizeObserver` 监听容器尺寸，并用单个 RAF 合并同一帧内的多次尺寸变化；
- resize 后按新尺寸绘制一帧；
- 卸载时取消动画帧、尺寸帧，断开观察器和媒体查询监听，移除事件并释放 WebGL 上下文；
- WebGL 初始化失败时保留容器和页面内容，不影响首页使用。

### 4.5 首页参数

- 首页继续保留当前密度、色相、辉光、旋转速度和透明度；
- 由于当前星空容器不可接收指针事件，首页明确关闭鼠标交互，避免无效状态计算；
- 不改变 Hero 高度、文案、卡片和导航栏样式。

## 5. 组件边界

### 5.1 `Galaxy.tsx`

负责 WebGL 初始化、正确尺寸、限帧调度、可见性暂停、动效偏好和资源释放。新增可配置参数：

- `maxDpr?: number`，默认 `1.5`；
- `maxFps?: number`，默认 `30`。

组件不读取业务状态，也不修改页面滚动行为。

### 5.2 `Home.tsx`

只提供首页视觉参数，并将 `mouseInteraction` 设为 `false`。不承担调度和性能策略。

### 5.3 `Galaxy.css`

继续保证容器与 Canvas 填满 Hero 背景。增加对 Canvas 显示尺寸和静态状态必要的保护，不引入大面积滤镜或新动画。

## 6. 状态与调度流程

```text
组件挂载
→ 创建 Renderer（受控 DPR）
→ 建立 ResizeObserver / IntersectionObserver / visibility / reduced-motion 监听
→ 计算容器 CSS 尺寸并渲染首帧
→ 若 active，启动受 30 FPS 限制的 RAF

active = 视口相交 && 标签页可见 && 非 reduced-motion

active 变为 false
→ 取消 RAF，不再 renderer.render

active 重新变为 true
→ 重置上一绘制时间，从当前时间继续 RAF

组件卸载
→ 取消全部 RAF
→ 断开观察器和监听器
→ 移除 Canvas 并释放 WebGL 上下文
```

## 7. 性能预算

在相同浏览器、相同视口、DPR 2、4 倍 CPU 降速的基准环境中：

- 首页 3 秒全页滚动平均帧率目标不低于 `110 FPS`；
- P95 帧间隔不高于 `12 ms`；
- 不出现超过 `50 ms` 的 Long Task；
- Galaxy Canvas CSS 宽高不得超过容器 CSS 宽高；
- DPR 上限后的缓冲区宽高不得超过容器 CSS 宽高的 `1.5` 倍；
- Galaxy 完全离开视口后，持续 WebGL 绘制应停止；
- `prefers-reduced-motion: reduce` 下只允许静态首帧。

如果运行机器的物理刷新率低于 120 Hz，则以“不低于可用刷新率的 90%”和 P95 不超过一个刷新周期的 1.25 倍作为等价标准。

## 8. 测试策略

### 8.1 红灯性能回归

在修改生产代码前运行真实浏览器脚本，固定 DPR 2 与 4 倍 CPU 降速，确认当前首页达不到 `110 FPS` 且 Canvas 尺寸超过容器，形成可解释的红灯。

### 8.2 组件行为验证

- DPR 2 环境下检查 Canvas CSS 尺寸和 backing store 上限；
- 统计可见状态下的 WebGL 绘制次数，确认约为 30 FPS 而非跟随 120 Hz；
- 滚出 Hero 后确认绘制计数停止增长；
- 切换 `prefers-reduced-motion` 后确认只保留静态帧；
- 返回视口后确认动画可恢复；
- 页面卸载后确认 Canvas 和监听生命周期被清理。

### 8.3 回归验证

- 重新运行同一滚动基准，记录前后平均 FPS、P95、P99 和最大帧间隔；
- 对首页与课程页进行桌面和移动端滚动验证；
- 检查 Galaxy 视觉、Hero 文案可读性、导航栏变形和页面跳转；
- 运行学生端 TypeScript 类型检查、生产构建和差异空白检查；
- 浏览器控制台不得出现新的错误。

学生端当前没有自动化测试运行器，本次不新增测试框架；性能红绿验证使用可重复的真实浏览器基准脚本与浏览器行为断言。

## 9. 风险与回退

- 30 FPS 会降低星空自身的时间采样频率，但该动画速度慢、属于背景装饰，滚动流畅度优先；
- DPR 1.5 在高分屏上会略微降低极细星点锐度，预期不影响整体视觉；
- 如视觉验收认为星空过于静态，可仅把 `maxFps` 调到 `45`，不撤销离屏暂停和 DPR 修复；
- 修复集中在 Galaxy 组件与首页参数，回退不影响业务页面和数据。

## 10. 成功标准

学生端首页在高分屏和中端设备模拟条件下恢复接近设备刷新率的滚动表现；Galaxy 动态星空仍然存在；离屏、后台标签和减少动态效果场景不再持续占用 WebGL；课程、作业、社区、AI 助教等其他学生端页面的布局和业务行为保持不变。
