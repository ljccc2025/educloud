# 学生端学习互动中心设计

## 背景

学生端已经具备课程、直播、作业、考试、订单和个人中心，但缺少学习过程中的消息触达、即时答疑和同伴交流。此前已确认采用方案 A：在现有学生端信息架构中增加三个独立入口，而不是把所有能力堆叠进个人中心或首页。

## 已确认范围

- 新增通知中心、AI 助教和学习社区三个受登录保护的页面。
- 通知中心由顶部铃铛进入，并显示未读数量。
- AI 助教提供完整聊天交互和可替换的请求适配器；当前无后端模型服务时使用明确标识的 Mock 应答，不伪装成真实模型调用。
- 学习社区支持浏览、搜索、发布、点赞、收藏和回复等前端核心交互。
- 使用适合后续微服务 API 接入的类型和状态边界，但本阶段不添加后端、鉴权协议或真实持久化。
- 保持学生端既有米白、深靛蓝和琥珀色视觉体系，不调整课程、作业和考试业务。

## 信息架构

### 导航

- 顶部通知铃铛改为指向 `/notifications` 的链接，并从通知状态中读取未读数量。
- 桌面主导航增加“AI 助教”和“学习社区”。
- 移动菜单增加通知中心、AI 助教和学习社区入口。
- 为避免新增入口造成导航挤压，桌面导航缩小间距，课程搜索框仅在 `xl` 及以上显示；各视口不得产生横向溢出。

### 路由

- `/notifications` → 通知中心。
- `/ai-assistant` → AI 助教。
- `/community` → 学习社区。
- 三个路由均复用现有 `ProtectedRoute`，未登录用户跳转到 `/login`。

## 模块设计

### 通知中心

通知数据包含类型、标题、内容、时间、已读状态和可选业务跳转。页面提供：

- 全部、未读两种筛选。
- 单条标记已读。
- 全部标记已读。
- 点击业务按钮后先标记已读，再进入课程、作业、考试或直播页面。
- 空筛选结果使用稳定的空状态，不改变页面整体宽度。

通知状态独立存放在 Zustand store 中。后续通知微服务接入时，只需把初始化和写操作替换为 API，不影响页面组件。

### AI 助教

页面由对话区和常用提问区组成：

- 支持输入问题、快捷提问、发送中状态、错误提示和清空会话。
- 消息区区分学生与助教角色，并在新消息产生后滚动到末尾。
- 请求通过 `assistantClient.ask()` 统一调用。
- 如果配置 `VITE_AI_ASSISTANT_ENDPOINT`，客户端向该后端端点发送请求；未配置时返回课程场景 Mock 应答。
- 浏览器端不保存或暴露大模型 API Key。真实模型调用必须由后端代理完成。

### 学习社区

社区页面包含帖子流和辅助信息栏：

- 按最新、热门、我的收藏筛选。
- 按标题、正文、课程或标签搜索。
- 发布讨论时校验标题和正文，成功后新帖子置顶。
- 支持点赞、收藏、展开讨论和发布回复。
- 所有计数随操作即时更新，重复点赞或收藏可以撤销。

社区数据和操作封装在独立 Zustand store 中。当前数据仅在页面会话内保存；后续社区服务接入时保持操作签名不变。

## 数据与错误边界

- Mock 数据使用固定值，禁止在渲染时使用随机数，避免界面跳动和测试不稳定。
- Zustand 更新采用不可变数组操作，使用函数式更新避免闭包中的旧状态。
- AI 请求捕获网络、响应格式和服务端错误，页面显示可重试提示并保留用户消息。
- 发布讨论和回复拒绝只包含空白字符的内容。
- 不执行 HTML 注入，所有正文由 React 文本节点渲染。

## 响应式与性能

- 页面主容器沿用 `max-w-7xl` 与现有断点。
- AI 对话区在桌面采用两列，在移动端折叠为单列；消息容器限制高度并独立滚动。
- 社区内容在桌面采用主列表加侧栏，移动端侧栏下移。
- 长列表项使用稳定 `id` 作为 key；筛选结果通过 `useMemo` 计算。
- 不引入新的 UI 框架或图表依赖，避免增加包体和视觉不一致。

## 验收标准

1. 登录后可从桌面和移动导航进入三个页面，刷新路由不会跳回首页。
2. 通知未读数量、筛选、单条已读和全部已读行为正确。
3. AI 助教可以发送问题、展示发送状态和回答；Mock 与真实端点模式边界清晰。
4. 社区可以搜索、筛选、发布帖子、点赞、收藏和回复，计数与状态同步更新。
5. 1440px、1024px 和 390px 视口均无横向溢出、元素变形或导航挤压。
6. 三个页面无新增控制台错误，原有学生端路由仍可访问。
7. TypeScript 检查和学生端生产构建通过。

## 验证策略

- Playwright 先在缺少路由的现状下运行失败回归，再在实现后验证三个页面的核心交互。
- 分别验证桌面和移动视口的页面宽度、导航入口与主要操作。
- 运行 `pnpm typecheck`、`pnpm build` 和 `git diff --check`。
- 使用中文代码审查检查正确性、错误处理、响应式布局、性能和变更范围。
