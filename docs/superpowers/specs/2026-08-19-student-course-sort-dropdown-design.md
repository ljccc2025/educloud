# 学生端课程排序弹层视觉统一设计

## 1. 目标

将学生端“课程中心 → 全部课程”搜索栏右侧的原生排序下拉框，调整为与教师端“内容管理 → 选择课程”一致的自定义弹层视觉语言。排序控件继续提供“最受欢迎、最新发布、价格从低到高、价格从高到低、评分最高”五个选项，原有筛选和排序结果保持不变。

本次只统一弹层外观、状态反馈和键盘交互，不增加课程封面、学员数等内容，也不修改课程数据、排序字段或后端接口。

## 2. 现状与设计依据

学生端 `CourseList.tsx` 当前使用浏览器原生 `<select>`。展开后的选项面板由操作系统和浏览器控制，呈现直角边框、系统蓝色选中态，无法稳定继承项目的圆角、阴影、配色和过渡效果。

教师端 `CourseSelect.tsx` 已建立本项目认可的自定义选择器样式与行为：

- 白色圆角触发器；
- 开启时使用靛蓝描边和轻微聚焦环；
- 白色圆角弹层、柔和边框和大面积阴影；
- 淡紫色悬浮、键盘高亮和选中状态；
- 当前选项带勾选图标；
- 箭头随展开状态旋转；
- 支持点击外部、方向键、Enter 和 Escape。

学生端排序项只有短文本，不需要复制教师端课程封面、章节数量和学员数。视觉采用用户确认的 A“紧凑复刻”方案：继承教师端组件语言，同时维持排序控件的轻量尺寸。

## 3. 组件设计

### 3.1 组件边界

新增学生端专用组件：

- `educloud-frontend/student-portal/src/components/CourseSortSelect.tsx`

组件只负责排序选择器的展示和交互，通过属性接收：

- 当前排序值；
- 排序选项数组；
- 选项变化回调。

`CourseList.tsx` 继续拥有 `sort` 状态、课程过滤和排序计算，只将现有原生 `<select>` 替换为 `CourseSortSelect`。组件不读取课程 Store，也不包含任何课程排序算法，避免展示组件与业务数据耦合。

### 3.2 触发器

触发器保持课程中心工具栏中的紧凑比例：

- 桌面端宽度约为 `13rem`，与搜索框并排；
- 窄屏下跟随现有纵向工具栏占满可用宽度；
- 使用白色背景、圆角、项目现有 `ink/indigo` 色板；
- 默认使用浅色边框，悬浮时加深；
- 展开时使用靛蓝边框、轻微聚焦环与阴影；
- 左侧显示当前排序标签，右侧显示下拉箭头；
- 箭头在展开时旋转 180 度。

### 3.3 弹层与选项

弹层定位在触发器下方并右对齐，宽度至少与触发器一致：

- 顶部保留小间距，避免与触发器边框粘连；
- 使用白色背景、较大圆角、浅色边框和教师端同类柔和阴影；
- 层级高于课程卡片，且不改变页面文档流；
- 五个选项保持单行紧凑文本，不展示封面或辅助信息；
- 普通项使用中性文字颜色；
- 鼠标悬浮和键盘高亮使用淡紫背景；
- 当前选项使用更明确的淡紫背景、靛蓝文字和右侧勾选图标；
- 选项切换使用颜色过渡，不增加缩放或位移动画。

## 4. 交互与无障碍

### 4.1 鼠标交互

- 点击触发器切换弹层开关；
- 点击某个选项后触发现有 `onChange`，同步当前排序值并关闭弹层；
- 点击组件外部关闭弹层，不改变当前排序值；
- 再次点击触发器关闭弹层。

### 4.2 键盘交互

- 弹层关闭时，Enter、Space 或 ArrowDown 打开弹层；
- 弹层打开时，ArrowDown 和 ArrowUp 在五个选项间移动高亮；
- Enter 选择高亮项并关闭弹层；
- Escape 关闭弹层且不改变排序值；
- 打开弹层时，高亮索引定位到当前选项。

### 4.3 语义

- 触发器声明 `aria-haspopup="listbox"` 与实时 `aria-expanded`；
- 弹层使用 `role="listbox"`；
- 每个选项使用 `role="option"` 和准确的 `aria-selected`；
- 选项文本仍作为可读名称，不依赖颜色或勾选图标单独表达状态。

## 5. 数据流与行为保持

排序数据流保持不变：

```text
用户选择排序项
  → CourseSortSelect 调用 onChange(value)
  → CourseList 更新 sort 状态
  → 现有 filteredCourses useMemo 重新计算
  → 课程卡片按原规则重新排列
```

五种排序规则不作修改：

- 最受欢迎：按 `studentCount` 降序；
- 最新发布：保持现有反转逻辑；
- 价格从低到高：按 `price` 升序；
- 价格从高到低：按 `price` 降序；
- 评分最高：按 `rating` 降序。

清除全部筛选时仍将排序恢复为“最受欢迎”，组件随受控 `value` 自动更新显示。

## 6. 响应式与异常边界

- 桌面端排序触发器位于搜索框右侧，不压缩搜索框到不可用宽度；
- 窄屏下排序触发器占满一行，弹层宽度不超过可视区域；
- 弹层不产生页面横向滚动；
- 选项数组为空时触发器保持可见但不执行选择，弹层显示“暂无排序选项”；
- 当前值与选项数组不匹配时显示首个可用标签或“请选择排序”，禁止抛出运行时异常；
- 组件卸载或关闭后清理点击外部监听器，不残留全局事件监听。

## 7. 变更边界

计划只修改或新增：

- `educloud-frontend/student-portal/src/components/CourseSortSelect.tsx`；
- `educloud-frontend/student-portal/src/pages/CourseList.tsx`。

明确不修改：

- 课程 MOCK 数据和课程 Store；
- 现有五种排序规则；
- 分类、难度、价格和搜索筛选；
- 教师端 `CourseSelect.tsx`；
- 项目依赖版本、后端接口和其他学生端页面。

当前工作区存在大量用户未提交改动。实现必须使用精确、最小补丁，禁止覆盖、格式化或提交任何无关文件。

## 8. 验证策略

学生端当前没有自动化测试脚本，本次不为单个弹层引入新测试框架。使用真实浏览器行为断言建立可重复的红绿回归，并执行现有工程检查。

### 8.1 修复前红灯

- 打开学生端课程中心；
- 验证当前排序控件仍为原生 `<select>`；
- 验证页面中不存在 `listbox`、自定义选中勾选和可控弹层；
- 该断言在实现前应按预期失败，证明回归检查能捕获缺失的自定义弹层。

### 8.2 实现后绿灯

- 初始触发器显示“最受欢迎”；
- 点击触发器显示五个排序项；
- 当前项具有 `aria-selected="true"`、淡紫选中态和勾选图标；
- 选择“价格从低到高”后弹层关闭、触发器更新，课程价格按升序排列；
- 再次打开后高亮和勾选同步到当前项；
- 点击外部与 Escape 均关闭弹层且不改变当前值；
- ArrowUp、ArrowDown 和 Enter 能完成键盘选择；
- 清除全部筛选后触发器恢复“最受欢迎”；
- 桌面端和窄屏均无横向溢出，弹层不被课程卡片遮挡；
- 浏览器控制台没有新增错误。

### 8.3 工程检查

- 学生端 TypeScript 类型检查通过；
- 学生端生产构建通过；
- 目标文件差异空白检查通过；
- 工作区中原有用户改动保持不变。

## 9. 成功标准

学生进入课程中心后，排序控件与教师端“选择课程”具有统一的圆角、阴影、淡紫状态和勾选反馈，同时保留学生端工具栏的紧凑尺寸。五种排序行为、全部筛选和响应式布局均正常工作，且没有引入新依赖或影响其他页面。
