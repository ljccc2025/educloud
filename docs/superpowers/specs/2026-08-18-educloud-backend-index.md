> 日期：2026-08-18

> 状态：已评审设计基线
>
> 范围：学生端、教师端、管理端对应的后端目标体系与落地计划
>
> 事实口径：现状与目标双层描述

## 1. 文档目的

本套文档用于指导 EduCloud 从“三套可运行的 React/Vite Mock 前端”演进为具备真实认证、业务数据、权限、交易、教学、互动、搜索、分析和可运维能力的微服务系统。

文档不会把页面、占位字段或 Mock 数据描述成已实现的后端能力，也不会把推荐、AI 助手、真实支付或音视频直播等外部能力包装为已经落地。

## 2. 状态标签

所有能力必须使用下列标签之一：

| 标签 | 含义 |
|---|---|
| `【已实现】` | 当前仓库存在可验证实现 |
| `【前端 Mock】` | 仅有前端模拟数据、本地状态或演示交互 |
| `【目标设计】` | 已完成设计但尚未实现的后端能力 |
| `【后续规划】` | 不属于首期关键闭环 |
| `【待决策】` | 缺少业务、供应商、容量或安全输入，不能固化 |

判断事实时按以下顺序取证：实际代码与配置、当前技术规范、已确认设计、明确标注的假设。发现冲突时进入决策记录，不静默采用任一版本。

## 4. 已锁定的架构决策

| 决策 | 结论 |
|---|---|
| 文档组织 | 分层文档集，总索引统一导航 |
| 后端范围 | Gateway 加 11 个业务服务，不新增第 13 个服务 |
| 数据边界 | 每个服务拥有独立逻辑数据库和账号；开发环境可共用 MySQL 实例 |
| 外部入口 | 三套前端只能通过 Gateway 访问后端 |
| 同步通信 | REST；服务内部按既有 Spring Cloud 体系调用 |
| 异步通信 | RabbitMQ 领域事件，本地事务加 Outbox，消费者幂等 |
| 核心一致性 | 权威服务内强一致，跨服务最终一致并可补偿 |
| 认证 | 短期 Access Token、HttpOnly Refresh Token、服务端会话撤销 |
| 权限 | RBAC 加资源归属校验，前端判断不作为授权依据 |
| 敏感配置 | 不回显到浏览器；生产仅通过 Kubernetes Secret/CI，开发使用未提交环境变量；Nacos 只存非敏感配置 |
| 推荐能力 | 首期采用可解释规则；模型推荐属于后续规划 |
| AI 助手 | 当前为 Mock/可选远端适配；真实模型集成尚未成立 |
| 实施策略 | 按纵向业务闭环逐期交付，不批量生成空服务 |

## 5. 当前与目标概览

| 领域 | 当前状态 | 目标状态 |
|---|---|---|
| 三套门户 | React/Vite 页面和 Mock 交互 | 通过统一 API 适配层接入 Gateway |
| 认证 | 三端方式不一致，账号校验为 Mock | User 服务统一登录、刷新、注销和撤销 |
| 课程与教学 | 前端内存数据 | Course/Content 权威数据与完整状态机 |
| 交易 | 本地购物车，订单可被直接模拟为已支付 | Order/Payment 幂等交易与支付回调 |
| 互动 | 本地通知、社区、直播状态 | Notification/Live/Content 服务化 |
| 搜索与分析 | 前端筛选和 Mock 指标 | Elasticsearch 索引及 Analytics 聚合视图 |
| 推荐与 AI | Mock 推荐、AI 助手演示或可选远端接口 | 规则推荐优先，AI 在安全决策后单独落地 |
| 部署运维 | 无后端部署资源 | Docker Compose、Kubernetes、监控和恢复体系 |

## 6. 尚待项目方决策

这些事项不会阻塞核心后端设计，但在对应阶段开始前必须确认：

| 事项 | 最晚决策阶段 | 未确认时的处理 |
|---|---|---|
| 支付渠道和沙箱账号 | 订单支付阶段 | 只提供渠道适配器和明确标注的模拟渠道 |
| 音视频媒体服务、推流协议和回放来源 | 直播阶段 | 只交付直播控制面、聊天和回放元数据 |
| AI 模型、知识来源、成本和数据权限 | 派生能力阶段 | 保持 Mock 或禁用真实 AI 入口 |
| 退款资格和学习后退款政策 | 订单支付阶段 | 使用配置化规则，默认进入人工审核 |
| 生产容量、可用性目标、RTO/RPO | 生产就绪阶段 | 不编造容量与恢复承诺 |
| Node.js 固定版本和前端统一包管理策略 | CI 建设阶段 | 按当前三个锁文件分别安装 |

## 7. 变更控制

- 服务职责、权威数据归属、公共 API 和事件格式发生变化时，必须同步更新本套文档和追踪矩阵。
- 依赖版本升级需要记录兼容性、迁移步骤、验证结果和回滚方案。
- 规划能力只有在实现代码、数据库脚本、测试、联调和可观测性均具备证据后，才能改为 `【已实现】`。
- 不允许用空接口、静态响应或前端字段宣称真实支付、AI 判断、自动审核或自动运维已经存在。

## 8. 非目标

- 当前文档不引入多租户、服务网格、事件溯源或新的分布式事务框架。
- 不为追求服务数量而拆分新的 Admin、Assignment、Exam、Community 或 AI 微服务。
- 不在没有容量数据时设计分库分表、读写分离和复杂缓存层级。
- 不要求重写现有 UI 信息架构；联调优先通过适配层完成。
