# EduCloud 项目现状与差距基线

> 取证日期：2026-08-18
>
> 说明：本文件描述当前仓库事实，不代表目标能力已经实现。

## 1. 工程现状

当前仓库的主要交付物是 `educloud-frontend` 下三套独立应用：

```text
educloud-frontend/
├─ student-portal/
├─ teacher-portal/
└─ admin-portal/
```

当前未发现 Java/Kotlin 后端源码、Maven/Gradle 后端工程、SQL 迁移、Dockerfile、Docker Compose、Kubernetes 清单或后端自动化测试。项目 README 明确说明三套应用使用 Mock 数据且无需后端即可运行。

## 2. 已实现前端技术栈

| 项目 | 当前事实 |
|---|---|
| UI 框架 | React 18.3.1、TypeScript 5.5.4、Vite 5.4 |
| 路由 | React Router 6.27 |
| 状态管理 | Zustand 5 |
| HTTP 依赖 | Axios 1.7 声明，但绝大部分业务仍使用本地 Mock |
| 样式 | Tailwind CSS 3.4、应用级 CSS |
| 图标和日期 | Lucide React、Day.js |
| 管理端图表 | Recharts 2.12 |
| 学生端包管理 | pnpm，存在 `pnpm-lock.yaml` |
| 教师/管理端包管理 | npm，存在 `package-lock.json` |
| TypeScript | 开启 `strict`，但允许未使用局部变量和参数 |
| 现有脚本 | `dev`、`build`、`preview`、`typecheck` |
| 缺失脚本 | 未配置正式的单元测试、端到端测试和 lint 脚本 |

学生端开发端口为 `5173`，教师端为 `5174`，管理端为 `5175`。当前实际 Vite 配置尚未形成统一 `/api` Gateway 代理。

## 3. 学生端现状

### 3.1 页面范围

学生端包含登录、首页、课程列表、课程详情、我的课程、学习页、作业、考试、个人资料、订单、直播、通知中心、AI 助手和学习社区。

需要 Token 的页面主要包括我的课程、学习、作业、考试、资料、订单、通知、AI 助手和社区；直播详情当前为公开路由。

### 3.2 当前业务行为

| 能力 | 状态 | 说明 |
|---|---|---|
| 登录 | `【前端 Mock】` | 任意非空账号密码均可获得模拟 Token |
| 课程检索 | `【前端 Mock】` | 在本地数组上筛选、排序和分页 |
| 选课 | `【前端 Mock】` | 直接修改内存课程状态 |
| 学习进度 | `【前端 Mock】` | API 有本地更新方法，但学习页面未真正持久化调用 |
| 购物车 | `【前端 Mock】` | Zustand 本地状态；立即购买只加入购物车并跳转 |
| 订单 | `【前端 Mock】` | 创建方法可直接生成 `PAID` 订单，不是真实支付 |
| 作业 | `【前端 Mock】` | 可查看和筛选，提交/查看批改按钮缺少真实闭环 |
| 考试 | `【前端 Mock】` | 可展示状态，开始考试和查看详情未接真实流程 |
| 个人资料 | `【前端 Mock】` | 表单成功提示未持久化到服务端 |
| 通知中心 | `【前端 Mock】` | 会话内标记已读和导航 |
| 学习社区 | `【前端 Mock】` | 本地发布、回复、点赞和收藏 |
| AI 助手 | `【前端 Mock】` | 默认返回演示内容；仅配置 `VITE_AI_ASSISTANT_ENDPOINT` 后调用远端 |

AI 助手远端适配当前发送 `{ "question": "..." }` 并期望 `{ "content": "..." }`。浏览器未保存模型 API Key，这是需要保留的安全边界。

## 4. 教师端现状

教师端包含登录、仪表盘、课程管理、课程编辑、内容管理、直播管理、作业批改、考试管理、学生列表和教学分析。

| 能力 | 状态 | 说明 |
|---|---|---|
| 路由保护 | `【前端 Mock】` | TeacherLayout 没有统一 ProtectedRoute |
| Token | `【前端 Mock】` | 只在 Zustand 内存中保存，刷新即丢失 |
| 登录 | `【前端 Mock】` | 未校验真实教师身份 |
| 课程维护 | `【前端 Mock】` | 对本地数组增删改；封面“上传”实际是 URL 或占位图 |
| 章节课件 | `【前端 Mock】` | 课件上传只创建 URL 为 `#` 的元数据 |
| 直播 | `【前端 Mock】` | 本地创建、开始、结束，在线人数为模拟值 |
| 作业批改 | `【前端 Mock】` | 本地修改分数和反馈，未持久化 |
| 考试 | `【前端 Mock】` | 可创建草稿；发布、编辑和监考按钮无真实接口 |
| 学生和分析 | `【前端 Mock】` | 本地筛选和只读模拟指标 |

教师端退出按钮当前只导航到登录页，没有完整撤销认证状态。这是目标认证改造的 P0 缺口。

## 5. 管理端现状

管理端包含登录、仪表盘、用户管理、课程审核、内容审核、订单、财务、系统配置和操作日志。

| 能力 | 状态 | 说明 |
|---|---|---|
| 路由保护 | `【前端 Mock】` | 仅检查 `localStorage` 中是否存在 `admin_token` |
| 用户管理 | `【前端 Mock】` | 状态修改在内存完成；删除按钮未接完整处理 |
| 课程审核 | `【前端 Mock】` | 本地批准/驳回并保存原因 |
| 内容审核 | `【前端 Mock】` | UI 收集驳回原因，但当前 API 模型未实际保存原因 |
| 订单和财务 | `【前端 Mock】` | 本地分页、筛选和只读指标 |
| 系统配置 | `【前端 Mock】` | 浏览器模型包含 SMTP、MinIO 和 JWT 密钥字段 |
| 操作日志 | `【前端 Mock】` | 展示生成的本地日志数据 |

目标后端不得照搬“查询并回显所有密钥”的交互。系统配置页面需要拆分为非敏感业务配置、脱敏连接状态和受限连接测试；Secret 更新只走 Kubernetes Secret/CI 或本地未提交 `.env`，不经过产品 API。

## 6. 认证与授权差距

| 问题 | 风险等级 | 目标处理 |
|---|---|---|
| 三端登录均为任意非空账号密码 | P0 | User 服务真实认证和账号状态校验 |
| 学生/管理端 Token 存在 localStorage | P0 | Access Token 内存化，Refresh Token 使用 HttpOnly Cookie |
| 教师端没有路由保护 | P0 | 统一认证初始化、ProtectedRoute 和 401 恢复流程 |
| 前端只判断 Token 是否存在 | P0 | Gateway 验签，业务服务执行角色和资源权限 |
| 管理端可见敏感密钥模型 | P0 | 后端不回显，前端只保留脱敏状态和受限连接测试；Secret 更新移交运维面 |
| 缺少会话撤销和刷新 | P1 | Redis 会话、刷新轮换、登出/禁用撤销 |

## 7. 业务闭环差距

### P0：必须先解决

- 真实身份、权限、资源归属和审计。
- 课程、内容、作业、考试、订单等权威数据存储。
- 服务端状态机和统一异常契约。
- 支付成功不能由前端或普通业务接口直接伪造。
- 管理端敏感配置不能明文返回。

### P1：关键产品闭环

- 课程发布与审核版本。
- 免费/付费选课与学习权限。
- 课件进度、作业提交和批改。
- 考试开始、计时、交卷与评分。
- 通知投递、直播控制面和社区持久化。
- 订单支付、退款、对账和财务查询。

### P2：派生与增强能力

- Elasticsearch 检索和索引重建。
- 教师、管理端聚合分析与全局审计查询。
- 规则推荐、推荐反馈。
- 真实 AI 助手和音视频媒体集成。

## 8. 规范冲突与收敛结果

| 旧文档表述 | 发现的问题 | 本套文档结论 |
|---|---|---|
| 每个微服务独立数据库 | 实施示例又把所有表放入单一 `educloud` 数据库 | 每服务独立逻辑库；开发可共用实例但不共享账号和表 |
| 统一响应业务码为 200 | 容易导致 HTTP 层始终返回成功 | 使用真实 HTTP 状态加稳定业务错误码 |
| JWT 存在 localStorage | 与目标安全要求不一致 | Access Token 内存化，Refresh Token 使用 HttpOnly Cookie |
| 管理端统一编辑全部配置 | 会把 SMTP、MinIO、JWT 密钥暴露给浏览器 | 业务配置与运维密钥分离，密钥不回显 |
| 已规划 AI 推荐与助手 | 当前没有真实模型调用或治理 | 规则推荐优先，AI 明确列为后续规划 |
| 12 服务完整实现计划 | 当前仓库没有后端工程 | 按纵向业务闭环分阶段建设并逐项验收 |
