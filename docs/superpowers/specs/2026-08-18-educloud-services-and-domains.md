# EduCloud 服务边界与领域模块

> 状态：`【目标设计】`
>
> 原则：一个业务事实只有一个权威服务，其他服务只持有必要快照或派生视图。

## 1. 边界总表

| 服务 | 权威业务事实 | 不负责 |
|---|---|---|
| Gateway | 路由、入口安全、限流和追踪 | 业务编排、业务数据 |
| User | 身份、账号、用户档案、角色权限、会话 | 课程归属、订单和成绩 |
| Course | 课程、分类、教师关系、选课、课程评价与审核 | 章节课件、支付事实 |
| Content | 章节、课件、学习进度、作业、考试、社区和内容审核 | 课程价格、支付状态 |
| Order | 购物车、订单、价格快照、退款申请 | 渠道支付事实、选课数据 |
| Payment | 支付单、渠道回调、退款执行和对账 | 订单商品、课程访问权限 |
| Live | 直播计划、场次、聊天、观看和回放业务关系 | 对象二进制、课程主数据 |
| File | 文件元数据、上传会话和 MinIO 对象映射 | 课程或课件业务含义 |
| Notification | 站内通知、模板和投递任务 | 业务状态本身 |
| Analytics | 聚合指标和跨域审计查询视图 | 修改权威业务数据 |
| Search | Elasticsearch 检索索引 | 课程发布和内容编辑 |
| Recommendation | 规则推荐结果与反馈 | 课程权威数据、真实 AI 推理 |

## 2. Gateway

### 职责

- 为三套门户提供唯一后端入口。
- 根据 Nacos 服务发现结果路由 `/api/v1/**`。
- 校验 Access Token 的签名、有效期、签发方和受众。
- 生成或传递 `requestId`、`traceId`。
- 执行跨域、安全响应头、请求大小和基础频率限制。
- 统一处理不可路由、超时和下游不可用响应。

### 约束

- 不保存订单、用户、权限或课程等业务表。
- 不在过滤器中实现资源归属判断。
- 不聚合跨服务写操作，不把内部服务直接暴露到公网。
- 传递的身份上下文必须防止客户端伪造；业务服务仍需授权检查。

## 3. User 服务

### 聚合与模块

- 账号：用户名、邮箱、手机号、密码哈希、账号类型和状态。
- 用户档案：展示名称、头像、简介和个人偏好。
- RBAC：角色、权限、用户角色和角色权限。
- 会话：Refresh Token 会话、撤销和客户端类型。
- 平台公开配置：站点名称、Logo、备案号等非敏感信息。
- JWT 签名公钥状态：活动 `kid`、更新时间和轮换计划，不包含私钥。

### 主要命令

- 学生自助注册（由公开配置开关控制）、登录、刷新、注销和修改密码。
- 找回/重置密码为 `【后续规划】`；完成一次性令牌表、通知渠道和页面闭环前不暴露半成品接口。
- 锁定、禁用、恢复用户。
- 更新本人档案。
- 分配角色和权限。
- 更新非敏感平台公开配置。
- 不提供用户删除/匿名化命令；首期仅禁用或恢复，匿名化待专项合规方案批准。

### 主要查询

- 当前用户、用户详情和管理端用户分页。
- 当前用户权限集合。
- 平台公开信息。
- JWT 签名公钥的非敏感状态摘要。
- 头像由 User 授权后按页批量向 File 获取短期展示地址，不保存永久对象 URL。

### 领域事件

- 发布：`UserRegistered`、`UserStatusChanged`、`UserProfileChanged`、`RoleAssignmentChanged`。
- 订阅：文件删除/变更事件，用于头像引用状态维护。

### 业务约束

- 用户名、已验证邮箱和手机号保持唯一。
- 禁用或改密后撤销相关 Refresh 会话。
- 密码、Token 哈希和敏感凭据永不进入普通查询响应。

## 4. Course 服务

### 聚合与模块

- 课程分类。
- 课程根与不可变版本：公开发布版本、教师工作草稿、标题、价格和生命周期。
- 课程教师关系：负责人和共同授课教师。
- 课程审核版本与审核记录；审批原子切换发布版本。
- 选课关系和课程访问状态。
- 学生评价和课程评分汇总。

### 主要命令

- 创建、编辑、提交审核、审批、驳回、下架和归档课程。
- 维护分类和教师关系。
- 免费选课；消费已支付订单事件创建付费选课。
- 撤销或限制退款后的课程访问。
- 创建、修改或隐藏课程评价。

### 主要查询

- 门户课程列表、详情、分类、教师课程列表。
- 我的课程和课程学生列表。
- 管理端待审核课程。
- 给 Order 返回可信课程销售快照。
- 课程首次提交与审批读取本库的 Content 就绪投影；投影缺失、版本有缺口或没有已发布修订时失败关闭，不同步回调 Content。

### 领域事件

- 发布：`CourseCreated`、`CourseSubmittedForReview`、`CoursePublished`、`CourseChanged`、`CourseOffline`、`EnrollmentCreated`、`EnrollmentRevoked`、`CourseReviewChanged`。
- 订阅：`Order` 完整聚合流（`OrderPaid`、Order 权威发布的 `OrderRefunded` 执行业务副作用）、`CourseContent` 完整聚合流（`ContentRevisionPublished` 更新就绪投影）和 `User` 状态流；不直接以 Payment 的渠道退款结果裁决课程访问。

### 业务约束

- 只有负责人或共同授课教师可以编辑课程。
- 未审批课程不能发布；关键内容修改需要重新审核。
- 同一学生和课程最多存在一条有效选课关系。
- 课程价格由服务端销售快照决定，不能信任客户端金额。

## 5. Content 服务

### 聚合与模块

- 课程内容根、不可变修订、章节、课件和学习顺序。
- 学习进度和课程完成度。
- 作业、提交版本、评分和反馈。
- 考试、试题、选项、个人答卷和答案。
- 学习社区帖子、评论、点赞、收藏和内容状态。
- 课件、帖子等内容审核版本与记录。

### 主要命令

- 复制/维护内容草稿修订，提交、撤回内容审核并原子切换发布修订。
- 记录课件学习进度。
- 发布、关闭作业；提交、重交和批改作业。
- 创建、发布、开始、交卷和批改考试。
- 发布、编辑、隐藏社区内容；点赞、收藏和评论。

### 主要查询

- 课程目录和可访问课件。
- 学生作业状态、提交详情、考试状态和成绩。
- 教师待批改列表、考试管理和学生完成情况。
- 社区信息流和帖子详情。
- 管理端待审核内容。

### 领域事件

- 发布：`ContentRevisionPublished`、`CoursewareChanged`、`LearningProgressChanged`、`AssignmentPublished`、`AssignmentSubmitted`、`AssignmentGraded`、`ExamPublished`、`ExamSubmitted`、`ExamGraded`、`CommunityContentChanged`。
- 订阅：`CoursePublished`、`CourseOffline`、`EnrollmentCreated`、`EnrollmentRevoked`、`FileDeleted`。

### 业务约束

- 课件访问需要有效选课关系或授课权限。
- 学习完成度由服务端根据课件事件计算。
- 作业分数在 `0..totalScore` 内；考试分值合计必须等于总分。
- 答卷开始时保存题目快照，后续改题不影响进行中的考试。
- 点赞和收藏按用户、对象、类型唯一。

## 6. Order 服务

### 聚合与模块

- 购物车项。
- 订单和订单明细，包括订单项退款履约状态。
- 课程标题、价格等购买时快照。
- 订单取消、关闭和退款申请。

### 主要命令

- 添加、更新、删除购物车项。
- 创建订单、取消未支付订单、关闭超时订单。
- 处理支付成功/失败事件。
- 按订单项发起、审核或取消退款申请。

### 主要查询

- 学生订单列表和详情。
- 管理端订单列表。
- 给 Payment 返回可支付订单摘要。
- 给 Analytics 提供权威订单事件。

### 领域事件

- 发布：`OrderCreated`、`OrderCancelled`、`OrderPaid`、`PaymentCompensationRequested`、`RefundRequested`、带订单项/课程范围的 `OrderRefunded`。
- 订阅：`PaymentSucceeded`、`PaymentFailed`、`RefundSucceeded`、`CourseOffline`。

### 业务约束

- 订单金额由 Course 销售快照计算并固化。
- 同一幂等键只能产生一个订单结果。
- 已支付订单不能直接取消；必须进入退款流程。

## 7. Payment 服务

### 聚合与模块

- 支付单和支付渠道交易。
- 每订单唯一支付聚合和最多一个活动支付尝试。
- 原始回调去重记录。
- 退款单和渠道退款结果。
- 对账批次及差异。

### 主要命令

- 为有效订单创建支付单。
- 接收、验签和幂等处理支付回调。
- 发起退款并处理退款结果。
- 执行支付与退款对账。

### 主要查询

- 支付单状态、管理端支付明细、退款和对账差异。

### 领域事件

- 发布：`PaymentCreated`、`PaymentSucceeded`、`PaymentFailed`、`RefundSucceeded`、`ReconciliationMismatchDetected`。
- 订阅：`OrderCreated`、`OrderCancelled`、`PaymentCompensationRequested`、`RefundRequested`。

### 业务约束

- 验证渠道签名、商户标识、订单号、金额和币种。
- 渠道通知 ID 或渠道交易号保持唯一。
- 相同回调重复到达必须返回同一处理结果。
- `OrderCancelled` 关闭本地活动尝试并尽力关闭渠道；关闭后仍扣款或取消/回调并发成功时必须自动退款，不发布可履约成功。
- 有效期内支付但事件晚到按真实渠道支付时间履约；过期后扣款和重复扣款自动退款并告警。
- 没有真实渠道凭证时只允许明确标注的模拟渠道。

## 8. Live 服务

### 聚合与模块

- 直播间与课程关系。
- 直播场次和 `CREATED/LIVING/ENDED` 状态。
- 课堂聊天和禁言状态。
- 进入、离开和观看时长。
- 回放生成状态及 File 对象关联。

### 主要命令

- 创建、编辑、开始和结束直播。
- 进入/离开直播，发送和撤回聊天消息。
- 绑定回放文件。

### 主要查询

- 学生可参加直播、教师直播管理、直播间详情和回放。
- 回放列表在 Live 校验课程访问后按页批量向 File 获取短期地址，选课撤销后不再续签。

### 领域事件

- 发布：`LiveStarted`、`LiveEnded`、`LiveReplayAvailable`、`LiveAttendanceRecorded`。
- 订阅：`CoursePublished`、`CourseOffline`、`FileDeleted`。

### 业务约束

- 只有课程教师可以开始或结束直播。
- 已结束场次不能恢复为直播中。
- 聊天用户身份来自认证上下文，不接受客户端指定身份。
- 未确定媒体服务时，只实现控制面和元数据，不宣称真实推流。

## 9. File 服务

### 聚合与模块

- 上传会话、文件对象、对象键、哈希、媒体类型和大小。
- 文件状态：上传中、可用、隔离、删除。
- 业务绑定和访问授权记录。

### 主要命令

- 创建上传会话、确认上传完成、绑定业务对象、解除绑定和删除文件。
- 生成短期上传授权；下载授权只接受已完成终端用户业务授权的绑定所有者服务，并再次校验精确绑定。
- 执行限频、可审计的 MinIO 最小读写连接测试；不接收浏览器传入的密钥。

### 主要查询

- 文件元数据、面向绑定所有者服务的授权访问地址、上传状态和脱敏存储连接状态。

### 领域事件

- 发布：以 `FileObject` 为聚合的 `FileUploaded`、`FileBound`、`FileUnbound`、`FileDeleted`。
- 订阅：领域对象删除事件，用于解除绑定或延迟清理。

### 业务约束

- 服务端生成对象键；客户端不能指定任意 MinIO 路径。
- 上传完成时校验大小、媒体类型和对象存在性。
- 未绑定对象经过保留期后清理。

## 10. Notification 服务

### 聚合与模块

- 通知事实、接收人收件箱、模板和投递任务。
- 站内、邮件等渠道结果。

### 主要命令

- 由领域事件创建通知。
- 标记单条或全部已读。
- 重试投递和停用模板。
- 向当前管理员已验证邮箱发送限频、可审计的渠道测试邮件；不接收浏览器传入的 SMTP 密码。

### 主要查询

- 当前用户通知列表、未读数量、管理端投递结果和脱敏渠道状态。

### 领域事件

- 发布：`NotificationCreated`、`NotificationDelivered`、`NotificationDeliveryFailed`。
- 订阅：注册、选课、支付、审核、作业、考试、直播等需要通知的事件。

### 业务约束

- 同一业务事件、接收人和模板保持幂等。
- 通知失败不能回滚来源业务。
- 用户只能读取和修改自己的收件箱状态。

## 11. Analytics 服务

### 职责

- 消费领域事件构建教师分析、管理仪表盘、财务指标和全局审计查询视图。
- 提供按天、课程、教师和平台维度的聚合查询。
- 保留事件消费水位和重建能力。

### 约束

- 所有指标为派生数据，不修改来源服务状态。
- 金额指标必须来自 Order/Payment 权威事件。
- 全局审计视图可查询，但不能覆盖来源服务审计事实。
- 聚合延迟必须在响应中或监控中可见。

## 12. Search 服务

### 职责

- 消费课程和内容事件维护 Elasticsearch 索引。
- 提供关键词、分类、难度、价格、评分和发布时间检索。
- 支持全量索引重建、增量修复和失败任务重试。

### 约束

- 只索引已发布且可见的课程/内容。
- Search 返回匹配 ID 和展示快照，不成为课程权威来源。
- 索引可被删除并从权威事件或批量接口重建。

## 13. Recommendation 服务

### 首期职责

- 根据课程热度、分类偏好、学习历史和规则权重生成课程排序。
- 保存推荐批次、理由和用户反馈。
- 在依赖不可用时降级为热门课程。

### 后续职责

- 在完成模型、知识源、隐私、成本和安全评审后增加 AI 助手适配模块。

### 约束

- 首期推荐必须可解释并保留规则版本。
- 不保存模型供应商密钥到前端。
- 推荐结果不绕过课程可见性和用户权限。

## 14. 管理端能力归属

| 管理端页面 | 权威服务 | 聚合/辅助服务 |
|---|---|---|
| 用户管理 | User | Analytics 统计 |
| 课程审核 | Course | Notification、Analytics |
| 内容审核 | Content | Notification、Analytics |
| 订单管理 | Order | Payment 状态快照 |
| 财务管理 | Payment、Order | Analytics 聚合 |
| 系统配置 | User 公开配置；User/File/Notification 仅提供脱敏状态与受限测试，不提供 Secret 更新 API | Kubernetes Secret/CI 运维面；服务健康跳转 Grafana |
| 操作日志 | 各来源服务产生事实 | Analytics 统一查询视图 |

## 15. 禁止的耦合

- 一个服务直接读取另一个服务数据库。
- 公共模块包含 Course、Order、Exam 等领域实体。
- Analytics、Search 或 Recommendation 反向修改权威数据。
- Notification 通过同步调用决定来源业务是否成功。
- Gateway 根据多个服务结果执行交易状态迁移。
- 前端直接调用 Payment 渠道、MinIO 管理端或内部服务地址。

## 16. 事件顺序约束

- `eventVersion` 只表示事件结构，`aggregateVersion` 表示业务聚合的单调版本。
- “订阅”章节列的是产生业务副作用的事件，不代表队列只绑定这些事件。投影依赖某聚合类型后，传输层必须把该聚合的所有事件信封送入同一投影队列；无关事件作为 no-op 在 Inbox 同事务推进最后版本，不能丢弃后制造假缺口。
- Course、Enrollment、Order、Payment、File 等状态投影按 `aggregateType + aggregateId` 路由，并保存最后应用版本。
- `EnrollmentRevoked`、`CourseOffline` 等撤销类事件不能被较旧的创建/更新事件覆盖。
- 消费者发现版本缺口时停止推进该聚合并触发快照校准，不猜测或跳过缺失状态。
